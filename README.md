# TradeLedger

Fullstack CRM для ручного учёта торговли: товары, счета ФОП MONO/NovaPay, личные долги и история балансов. Русский интерфейс, UAH, пустой новый аккаунт. React обращается к NestJS API; учёт и сессии хранятся в PostgreSQL. Банковских интеграций нет.

## Запуск

Нужны Docker Desktop, Node.js 24.15+ (ветка 24) и npm. Из папки проекта:

```sh
npm ci
node scripts/local-stack.mjs up
```

Откройте [TradeLedger](http://127.0.0.1:5178) и войдите в предоставленный владельцем аккаунт. Docker запускает web на 5178, API на 5180 и PostgreSQL на 5439, только на loopback. Скрипт создаёт локальные пароли в памяти при первом запуске; при следующих использует настройки существующего принадлежащего проекту контейнера. Пароли не нужно записывать в `.env` или передавать в командной строке. Данные сохраняются в именованном Docker volume `tradeledger-postgres-v1`; остановка контейнеров их не удаляет. Состояние: `node scripts/local-stack.mjs status`; остановка: `node scripts/local-stack.mjs stop`. Не удаляйте volume для перезапуска.

Для разработки после запуска API можно открыть Vite на том же адресе через tmux:

```sh
node scripts/local-stack.mjs api
tmux new -s tradeledger-web 'npm run dev -- --port 5178 --strictPort'
```

Порт 5178 должен быть свободен: сначала остановите web-контейнер через `node scripts/local-stack.mjs stop`, затем снова запустите `api`. Vite проксирует `/api` на 5180 и сохраняет исходный Origin. Полный Docker-запуск не требует Vite.

## Учёт и доступ

- Войдите по электронной почте и паролю. Регистрации в интерфейсе нет; доступ предоставляет владелец TradeLedger. Сессия хранится в HttpOnly SameSite cookie; «Выйти» отзывает её на сервере и очищает видимый учёт. Ответ выхода не перезаписывает cookie, чтобы задержанный выход другой вкладки не затёр более новый вход; отозванный токен больше не даёт доступа. В другом браузерном контексте тот же аккаунт видит сохранённые записи, другой аккаунт — собственный пустой набор. Публичного размещения и восстановления пароля в этом локальном запуске нет.
- В «Складе» внесите артикул, целое количество и закупочную цену. Приход увеличивает количество и стоимость; списание уменьшает стоимость пропорционально остатку с округлением до копейки. Последняя единица списывает остаточную стоимость. Средняя цена приблизительная; точна стоимость остатка.
- В «Счетах» внесите фактические остатки MONO, NovaPay или другого провайдера. Обновление заменяет баланс; отрицательные значения допустимы.
- «Изменение денег за месяц» в обзоре и счетах — текущая сумма всех счетов минус остаток на конец прошлого календарного месяца, **не прибыль**. Сервер автоматически закрывает месяц первого числа в 00:00 по `Europe/Kyiv`, с учётом переходов летнего времени и независимо от часового пояса сервера. При сбое БД делает не более трёх разовых повторов через 30 секунд, 2 и 10 минут; при успехе повторов нет. При запуске он восстанавливает все пропущенные закрытия из истории состояний счетов на соответствующие границы; более поздние остатки, переименования и счета в старые месяцы не попадают. Повторный запуск не создаёт дубликатов. Открытая вкладка обновляет учёт при смене месяца (один ограниченный повтор, если чтение опередило транзакцию закрытия), при фокусе или возвращении к вкладке.
- История для автоматического закрытия начинается с текущего состояния при первом запуске новой версии либо с фактического времени восстановления копии. Балансы до начала этой истории не выдумываются: без официального закрытия именно прошлого месяца показывается «Нет данных за прошлый месяц». Импортированные исторические даты и прежние ручные фиксации сохраняются в истории и графике, но не заменяют официальное закрытие. Ручной кнопки фиксации больше нет. В JSON у официального закрытия есть `closedMonth: "YYYY-MM"` и точная дата следующей месячной границы по Киеву; явное закрытие из копии сохраняется при восстановлении, не расширяя покрытие журнала назад. Карточка указывает сравниваемые месяцы и границу закрытия; разница вне безопасного диапазона отображается явно. Каждое закрытие хранит названия, владельцев, провайдеров и балансы счетов на тот момент.

- В «Долгах» выберите «Я должен» или «Мне должны» и погашайте сумму частично либо полностью. Закрытые долги остаются в истории. Склад, долги и банковские счета независимы: операции автоматически не меняют счета.
- Деньги вводятся с точкой или запятой и максимум двумя десятичными знаками; хранятся безопасными целыми копейками. Сервер проверяет команды и ревизию атомарно. Автоматическое закрытие увеличивает ревизию; если импорт одновременно закрывает прежний набор и заменяет его, ревизия увеличивается дважды в одной транзакции после проверки исходной версии. При конфликте вкладок черновик сохраняется: обновите данные, сверьте значения и подтвердите повтор. При потере сети сохранение сообщает ошибку; черновик остаётся, автономной очереди записей нет.
- Если другая вкладка сменит аккаунт, устаревшая вкладка не сможет записать данные или завершить чужую сессию: сервер сверяет cookie с ожидаемым пользователем запроса и требует повторный вход при несовпадении.

## Резервные копии и прежние данные

Раздел «Резервная копия» открывается по адресу `/#settings` (например, [в локальном приложении](http://127.0.0.1:5178/#settings)); в боковом меню его нет. Меню содержит пять основных разделов: «Обзор», «Склад», «Счета», «Долги», «История». В «Резервной копии» скачивайте JSON `schemaVersion: 1` (товары, счета, долги, фиксации балансов и история). Файл до 5 МБ проверяется до изменения данных. Восстановление после предпросмотра и явного подтверждения полностью заменяет активный набор; прежний набор архивируется на сервере, ревизия не сбрасывается. API позволяет скачать архив; объединения данных нет. JSON-копия учёта не заменяет резервное копирование PostgreSQL volume и данных аккаунтов.

Если в прежнем браузерном профиле и на прежнем origin сохранилась IndexedDB `tradeledger`, раздел переноса прочитает её без изменения. Сначала скачайте исходную копию, проверьте адрес аккаунта назначения и состав данных. Для непустого аккаунта отдельно подтвердите архивирование и полную замену. Успех показывается после проверки серверной квитанции: хеша источника, количества записей и сохранённой ревизии. Исходная IndexedDB не удаляется и не перезаписывается. После перезагрузки подтверждённый перенос распознаётся по серверной квитанции. Повреждённый источник не отправляется; доступно скачивание исходной копии и повторное чтение. Другой адрес/порт/профиль не имеет доступа к прежней IndexedDB.

Автоматического импорта Excel, банковских ключей, расчёта продаж/прибыли или бухгалтерской отчётности нет.

## Демо-данные

После запуска локального Docker-стека и подготовки общей доменной сборки:

```sh
npm run server:build
npm run seed:demo
```

Команда читает пароль отдельного демо-аккаунта из `TRADELEDGER_DEMO_PASSWORD` либо stdin (без аргументов командной строки и без вывода пароля). Передайте свой **демонстрационный** пароль длиной 12–256 символов через безопасный менеджер секретов или ввод без отображения; не используйте пароль рабочего аккаунта. Не записывайте его в `.env`, скрипты или историю shell. При запуске из интерактивного терминала без переменной команда откажется от работы; пароль передаётся через stdin заранее. Для последующего входа и повторного запуска нужен тот же пароль.

Сид работает только с `http://127.0.0.1:5178` и аккаунтом `tradeledger-demo-v1@example.invalid`; адрес сервера и аккаунт не переопределяются. Если аккаунта ещё нет, команда создаёт его обычным API регистрации. В production-окружении запуск запрещён. Рабочие аккаунты и исходная IndexedDB не затрагиваются.

Набор: 16 товаров электроники и аксессуаров (нулевые и малые остатки, приходы и списания), пять счетов ФОП MONO/NovaPay (включая отрицательный баланс), шесть долгов обоих направлений (открытые, частично погашенные и закрытые), десять фиксаций балансов за 3–21 октября 2026 года и 95 событий истории. Все суммы — целые копейки; данные и контрагенты вымышленные. Изменение денег не обозначает прибыль, подключения к банкам нет.

Документ создаётся общими доменными командами и валидатором, затем атомарно импортируется через защищённый API в пустой аккаунт. Исторические даты сохраняются в резервной копии; обычные команды API используют серверное время. Повторный запуск сравнивает весь набор и не меняет его. Если демо-данные вручную изменены или аккаунт уже содержит другой набор, сид откажется от записи. Сбоивший до фиксации импорт можно повторить; потерянный ответ после успешной фиксации не создаёт дубликатов. Автоматической очистки и сброса нет.

Для независимого от пароля JSON-файла выполните `npm run seed:export`: команда создаёт [`.cache/demo-seed-v1.json`](./.cache/demo-seed-v1.json) без учётных данных. Его можно выбрать в «Резервной копии», проверить предпросмотр и вручную подтвердить импорт в выбранный аккаунт. Импорт заменяет активный набор с архивированием прежнего; сначала сохраните рабочую резервную копию. Экспорт не подключается к серверу и не меняет аккаунты. Повторный экспорт сохраняет идентичный файл и откажется перезаписывать файл с другими данными.

`npm run seed:test` проверяет состав, финансовые итоги, ограничения назначения, повторный запуск и ошибки импорта без сетевых запросов. Перед ним также нужна `npm run server:build`.

## Проверки

После `npm ci` подготовьте локальный Prisma-клиент и сборку сервера (Docker собирает их внутри контейнера отдельно):

```sh
npm run db:generate
npm run server:build
npm test
npm run typecheck
npm run lint
npm run build
npm run server:unit
npm run server:integration
npm run test:e2e
```

Для HTTP/SQL и E2E нужен запущенный принадлежащий проекту PostgreSQL (`node scripts/local-stack.mjs db`). Каждая проверка создаёт и сохраняет отдельную БД `tradeledger_it_*`; рабочая БД не очищается и не заполняется тестовыми пользователями. Миграции применяются только к новой тестовой БД. HTTP/SQL тесты работают с настоящими PostgreSQL и собранным Nest-приложением.

E2E использует установленный Google Chrome, отдельные временные контексты, Vite 5179 и настоящий API 5181. Playwright запускает собственную среду, не переиспользует рабочий сервер и не применяет HTTP-моки или reset endpoint. Перезапуск API против той же тестовой БД и SQL-проверки выполняет локальный Unix-сокет, отсутствующий в приложении. Проверяются вход/выход, два контекста, разделение аккаунтов, смена cookie между вкладками, сохранение после перезапуска API, отказ записи без сети, legacy-перенос с квитанцией и архивом, склад, счета/фиксации балансов, долги, резервные копии, CAS-конфликт, клавиатура и размеры 1440×1000 / 390×844. Trace отключён, чтобы не сохранять пароли и cookie. Артефакты ошибок — `test-results`, контрольные снимки — `.cache/previews`. Мобильный viewport не подтверждает физический iPhone safe-area.

## Production на Hetzner

Отдельный ручной production-контур развёрнут на Hetzner: TradeLedger по HTTPS (адрес предоставляет владелец) с доверенным сертификатом Let’s Encrypt, закрытой публичной регистрацией и PostgreSQL без опубликованного порта. Ежедневные локальные копии БД включены, восстановление в новую БД проверено; off-host копирование пока не настроено. Локальный запуск выше работает отдельно. Настройка сервера, первый выпуск, создание пользователей, обновления, безопасный откат кода и проверка восстановления описаны в [production-инструкции](./deploy/production.md). CI/CD нет.
